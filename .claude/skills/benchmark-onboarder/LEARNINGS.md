## Common Patterns

- **Datasets requiring `trust_remote_code`**: Add `trust_remote_code=True` to `load_dataset()`
- **Suspected model output fields**: Check the paper to confirm field purpose before skipping
- **Misclassified benchmarks**: "Programming & Algorithmic Creativity" or "Scientific Discovery" tags don't automatically mean creativity benchmarks; check if the paper focuses on logical reasoning, problem-solving, or pattern discovery vs. creative generation. Inductive reasoning benchmarks (finding rules from examples) are not creativity benchmarks.
- **Audio/video/image generation benchmarks**: HELM evaluates text-based language models. Benchmarks that generate audio, music, images, or video as output (not text descriptions of them) are outside HELM's scope and require HEIM (for image generation) or similar audio generation frameworks. These are valid creativity benchmarks but need different evaluation infrastructure.
- **Multi-turn conversation benchmarks**: HELM uses single-turn Instance → References architecture. Benchmarks requiring multi-turn conversations with context maintenance across turns are outside HELM's scope. This includes dialogue systems, conversational agents, and hierarchical multi-turn evaluation frameworks. These need specialized conversation evaluation infrastructure.
- **Multilingual benchmarks are supported**: Non-English benchmarks (Chinese, Arabic, etc.) can be onboarded. HELM scenarios can handle any language in prompts/references. Many LLMs support multiple languages (GPT-4, Claude, Qwen, GLM). Don't reject benchmarks solely for being non-English.
- **Challenge "not_suitable" assessments**: Initial rejection reasons may be overly conservative. Verify by examining actual dataset structure and evaluation methods. Examples: PACE (initially "evaluation metric" → onboarded with custom metrics), DeepMath-Creative (initially "non-English" → onboarded as multilingual), MEMECAP (initially "images unavailable" → onboarded with separate download).
- **Evaluation frameworks can be benchmarks**: Repositories marked as "evaluation metric/framework" may still qualify if they have: (1) reusable prompts/test instances, (2) automated evaluation method, (3) clear task definition. Check for seed data, test sets, or prompt templates that can be used to evaluate new models.

## Multimodal Support in HELM

**HELM supports multimodal benchmarks** through `MediaObject` and `MultimediaObject` classes. Use these for benchmarks with images, audio, or video inputs.

|----------|-----------|---------------|---------|
| **Images** | `image/png`, `image/jpeg`, `image/gif`, `image/webp` | Local file path or HTTP(S) URL | Vision-language tasks, visual QA |
| **Audio** | `audio/mp3`, `audio/wav`, `audio/ogg` | Local file path or HTTP(S) URL | Audio understanding, speech tasks |
| **Video** | `video/mp4`, `video/webm` | Local file path or HTTP(S) URL | Video understanding tasks |
| **Text** | `text/plain` | Inline text (no location) | Part of multimedia sequence |

### When to Use Multimodal vs Text-Only

**Use MediaObject for:**
- Benchmarks where visual/audio content is essential to the task
- Vision-language models (VHELM framework)
- Tasks requiring actual image/audio understanding

**Use text descriptions for:**
- Spatial/visual information that can be serialized (see Sudoku-Bench)
- When models don't need to process actual media
- Text-only models being evaluated

## Style Conventions

- Scenario class names: `{Benchmark}Scenario` (e.g., `RiddlesenseScenario`)
- `name` field: lowercase with underscores (e.g., `riddlesense`)
- `description` field: data source reference, not task description
- Always include `tags = ["creativity", ...]`
