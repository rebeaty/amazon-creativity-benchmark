# Metric Notes: PunEval — Custom Generation Metrics

Source: arXiv:2404.13599; https://github.com/Zhijun-Xu/PunEval (Notebook 6)

The paper introduces four custom metrics for pun generation quality beyond binary pun detection.
These require NLP tooling not natively available in HELM and need custom implementation.

---

## Metric 1: Ambiguity

**Definition:** Whether the generated sentence can be interpreted under both meanings of the
pun keyword simultaneously (the core property of a successful pun).

**Implementation:**
- Find two synonyms for the pun keyword (one per meaning) using the LLM synonym-finding prompt
  (see below)
- Compute GloVe/SkipGram embedding similarity between the sentence (excluding the keyword)
  and each synonym
- **Ambiguity = min(sim_synonym1, sim_synonym2)** — the minimum similarity captures whether
  both meanings are evoked

**Synonym-finding prompt** (verbatim from Notebook 6):
```
<*Instruction*>
Below is a pun text, one keyword, and its two meanings. The keyword is the pun in the text,
which can be interpreted in two meanings. Please find two different synonyms for the keyword,
each corresponding to one of the meanings. The synonyms should be able to replace the keyword
in the text seamlessly to remove ambiguity, while ideally being a simple word. You must output
the current status in a parsable JSON format. An example output looks like:
{'Synonym 1 for Meaning 1': 'XXX', 'Synonym 2 for Meaning 2': 'XXX'}

<*Your Response*>
Text: {RESPONSE}
Keyword: {pun_word}
Meaning 1: {pun_word} <{pun_sense}>
Meaning 2: {alter_word} <{alter_sense}>
Output:
```

**Tooling required:** GloVe embeddings (glove.6B.300d or similar), or SkipGram word2vec.

## Metric 2: Distinctiveness

**Definition:** Whether the two meanings are sufficiently different (not redundant).
A good pun exploits genuinely distinct meanings.

**Implementation:**
- Use the same two synonyms from Metric 1
- Compute GloVe/SkipGram similarity between the two synonyms
- **Distinctiveness = 1 − sim(synonym1, synonym2)**

**Tooling required:** Same GloVe/SkipGram embeddings as Metric 1.

---

## Metric 3: Surprise

**Definition:** How unexpected the pun is in its sentential context — the punchline should be
surprising given the preceding context.

**Implementation (paper):**
- Split the generated sentence at the pun keyword
- Compute similarity between the sentence context (before keyword) and each synonym
- **Surprise** = difference between the two context-synonym similarities
  (high surprise = context primes one meaning, then switches to the other)

**Tooling required:** GloVe/SkipGram embeddings; sentence splitting at pun_word position.

---

## Metric 4: Unusualness

**Definition:** Perplexity-based measure of how linguistically surprising the pun sentence is
compared to a baseline non-pun sentence using only one meaning.

**Implementation (paper):**
- Score the pun sentence using a unigram language model (trained on a large corpus)
- Score the baseline non-pun sentence (generated by Method 0 in Notebook 5)
- **Unusualness = LM_score(baseline) − LM_score(pun_sentence)**
  (positive = pun sentence is more unusual/surprising than baseline)

**Tooling required:**
- fairseq `SequenceScorer` (or similar unigram LM)
- Method 0 non-pun baseline sentences (requires running generation first)

## Implementation Priority

| Metric | Complexity | HELM Priority |
|--------|-----------|---------------|
| Pun Detection (LLM judge) | Low | **Implemented** (see annotator_notes.md) |
| Ambiguity | Medium (embeddings + LLM synonyms) | High — core pun quality |
| Distinctiveness | Low (embeddings only) | Medium |
| Surprise | Medium (embeddings + splitting) | Medium |
| Unusualness | High (requires LM scoring + baseline) | Low |
